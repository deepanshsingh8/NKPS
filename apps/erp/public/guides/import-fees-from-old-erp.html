Import fee records from the old ERP

Bring every receipt from the old software into the new ERP in one upload, as often as you like, without entering any receipt twice.

Fees → Payments → Import Day Book (Head wise)
Takes about ten minutes · Admin or editor with the Fees permission

Before you start

  • The session's fee schedule is published for every class (Fees → Academic Fees). A receipt can only land on an instalment that exists.
  • Every bus student has a bus stop assigned for the session, and the stop has a fee (Transport → Stops / Student Assignments). The bus fee column lands on those months.
  • The old software's Day Book (Head wise) Report, exported as .xls for the whole session to date. Export it fresh each time; do not edit it.

How duplicates are avoided

You can upload the same, or a later, export again and again. Three checks run on every receipt before anything is written:

Old receipt number A receipt already imported is matched by its old number and skipped as Already imported. If its total changed in the old software, it becomes a Conflict that you resolve by hand.
Entered by hand on the fee desk A receipt with the same student, date and amount as a payment you recorded directly in the ERP is skipped as Already in ERP.
Held back for you to check When a student has a hand-entered payment that matches nothing in the file, the rest of their receipts wait as Needs review. The row names the payment to check in Payment History. Tick “import their receipts too” once you are sure it is different money.

The six steps

  1. Export the Day Book from the old software

    Reports → Day Book (Head wise), from the first day of the session to today, saved as .xls. One file for the whole session; the importer skips what it has already seen, so the overlap with your last export is harmless.

    The Account-wise report is a different layout and uses the other button. Use Head-wise: it carries the receipt number, the payment mode and the fee head, which is what makes re-uploads safe.

  2. Open the importer in the ERP

    Go to Fees → Payments. Above the class picker, click ⇧ Import Day Book (Head wise). The dialog has a link to this guide.

    Nothing is written until you press Import in step 6. You can close the dialog at any point.

  3. Pick the session, choose the file, click Preview

    Select the session the receipts belong to (normally the current one), choose the .xls, and click Preview. Leave both boxes ticked: students who paid but are not on the roster are created as inactive records so their money has an owner, and a receipt with no SR number is matched by the student's and father's names when exactly one student fits.

  4. Read the reconciliation and the counters

    The first panel compares three totals: what the file's own footer says, what the ERP read from it, and what this run will write. The first two must be equal; if they are not, stop and send the file to support. Below them, the counters say what happens to each receipt. Green imports; grey is already in the ledger and skipped; amber waits for your decision; red blocks the import until fixed.

    “Fee rows” is larger than “receipts” because one receipt that paid two instalments, or several bus months, becomes one row per instalment or month, all sharing the receipt number.

  5. Map anything it did not recognise, review what is held back

    A class name or a fee head the ERP does not know gets a dropdown: pick the ERP class or head it means, then click Preview again. A Bus Fee / Transport / Conveyance column is recognised on its own; map any other name for it to Transport. Tuition and admission heads fill that head's instalments oldest first; the bus head fills the student's bus months oldest first, and June is never charged, so it is never filled.

    Rows marked Needs review name a hand-entered payment to check. Open the student in Payment History; if the hand-entered payment is genuinely different money, tick “I have checked these students — import their receipts too” and Preview again. A Conflict or an error must be fixed first: correct the receipt in the ERP, or revert the batch that created it, then re-run.

  6. Import, then check one student

    When the counters show no errors and no conflicts, click Import. The batch appears under Import history with the count, the amount and a Revert that removes the whole batch if something was wrong. Open one or two students afterwards: their instalment cards should read Paid, and each bus month should be green.

    Imported receipts carry the number DB-2026-<old receipt>-1 (and -2, -3 for a receipt split across instalments). The old number is also searchable in Payment History.

Working day to day

Payments recorded on the fee desk and payments imported from the old software live in the same ledger. Keep recording today's receipts in the ERP; when the old software's export arrives, upload it. Receipts you already keyed in are matched and skipped, and only the rest come across.

A parent paying the bus fee for the whole year: in Record Payment, click “Tick rest of session” under Bus fee; every month still unpaid is ticked and the amount fills in. Months not yet due can always be ticked to pay in advance.

If something looks wrong

  • A student shows no Paid / Due line under the fee cards: the browser window is on an older build. Reload the page; a “new version is available” message offers it.
  • The same receipt appears twice: revert the newer batch from Import history, then re-upload.
  • “Pays a bus fee, but the student has no bus stop”: assign the stop under Transport, then Preview again.
  • “The database still has the old receipt index”: ask the administrator to run migration 141, then import again.
